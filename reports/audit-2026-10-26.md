**neo-control** is a React/Vite canvas arcade game. Both the build and tests pass cleanly, but lint fails with one blocking error (`setState` called synchronously inside a `useEffect` in `AdminPage.tsx`). Two critical ARIA violations in the game canvas make HUD controls and briefing overlays invisible to assistive technology. The codebase has intentional architectural debt in `GameCanvas.tsx` (3277 lines) and `AdminPage.tsx` (1509 lines) — justified by the canvas game-loop constraint but worth tracking.

**where-it-counts** is a SvelteKit/D3 scrollytelling piece. Build and tests pass; no lint toolchain is configured. Two critical A11Y gaps: the D3 choropleth visualization is hidden entirely from screen readers via `aria-hidden`, and the direction toggle uses incorrect ARIA semantics. One medium-severity security finding: `{@html}` in `Scrollytelling.svelte` has no sanitization.

## 2. Build / Lint / Test Health

### neo-control
- `npm run build`: ✅ Pass — 77 modules, 344 kB JS (107 kB gzip), 375ms
- `npm run test`: ✅ Pass — 11/11 tests
- `npm run lint`: ❌ **1 blocking error**
  ```
  AdminPage.tsx:1173 — Calling setState() directly within an effect
  useEffect(() => { if (authed) load(); }, [authed]);
  ```
  `load()` is an async fetch that sets multiple state values; the rule `react-hooks/set-state-in-effect` fires because it calls a setState-containing function synchronously (not in a callback). **Fix:** Wrap in an async IIFE or move the `load()` call inside the effect body directly, then suppress if the pattern is intentional: `// eslint-disable-next-line react-hooks/set-state-in-effect` with a comment explaining why.

### where-it-counts
- `npm run build`: ✅ Pass — static output to `build/`, 6.19s
- `npm run test:ci`: ✅ Pass — 16/16 tests
- Lint: ❌ **No lint script configured** — no ESLint or svelte-check script in package.json. `svelte-check` is available via `@sveltejs/kit`'s peer deps. Fix: add `"check": "svelte-check --tsconfig ./tsconfig.json"` and `"lint": "prettier --check . && npm run check"` to package.json.

This is the only failing lint check; CI will block on it. Either refactor to call `load()` as an async IIFE inside the effect, or add a targeted disable comment with justification.

4. **[HIGH — where-it-counts] Add sanitization comment to `{@html}` in Scrollytelling.** `Scrollytelling.svelte:51` renders `step.text` as raw HTML with no sanitization. The data is currently a static constant (safe), but there is no guard against a future change that supplies dynamic content. Add an explicit code comment enforcing the static-only constraint, or add DOMPurify.

5. **[HIGH — both] Plan major-version dependency upgrades.** Four packages have crossed a major version boundary: TypeScript (6→7), ESLint (9→10) in neo-control; SvelteKit (2→3) and adapter-static (3→4) in where-it-counts. These will need dedicated upgrade PRs with migration testing — track them before the current versions lose security patch support.
