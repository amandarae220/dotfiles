# Monthly Audit — 2026-07-29 (sudoku, interactiveResume)

## Executive Summary

**sudoku** is in good shape: build passes cleanly, accessibility is strong, and code quality is high. Main concerns are a 357-line component that exceeds the 150-line limit, a handful of magic numbers, and several outdated dependencies (4 packages >1 major version behind).

**interactiveResume** has multiple critical issues requiring immediate attention: a missing `hexbinChart.js` file causes the skills hexbin chart to completely fail on page load; the gantt chart is inaccessible to keyboard/screen-reader users; two color pairs fail WCAG AA contrast requirements; and a reference to a commented-out DOM element throws a runtime `TypeError`. D3 is 2 major versions behind (v5 → v7).

## 1. Skill Compliance

### 🚨 Critical

**A11Y [severity: critical]: interactiveResume/index.html:62 — Missing `hexbinChart.js` script causes page-load error — Remove `<script src="hexbinChart.js"></script>`; hexbin code already lives in `ganttChart.js`**

The hexbin skills chart script is referenced but the file does not exist in the repo. Every page load triggers a 404 and the skills section fails silently. The hexbin rendering code is present inside `ganttChart.js` (lines 1–110), suggesting the scripts were once split but the HTML was never updated.

**A11Y [severity: critical]: interactiveResume/ganttChart.js:280 — Gantt chart bars have no keyboard access — Add `tabindex="0"`, `role="button"`, and `keydown` (Enter/Space) handlers to D3-rendered `<g>` elements**

The work-experience gantt chart is the primary interactive element of the page, but click events are the only input mechanism. Keyboard-only users and screen-reader users cannot select a role to view details.

**A11Y [severity: critical]: interactiveResume/style.css:51 / ganttChart.js:316 — `#57e0fa` (selected-state text) on `#FFFFFF` background = 1.56:1 contrast ratio; WCAG AA requires 4.5:1 for normal text — Change selected-hex text fill to a dark foreground color (e.g. `#1a1460`) instead of the highlight color**

When a hexagon skill is selected, text is changed to `#57e0fa` against the white page background. This fails contrast by a factor of ~3x.

**A11Y [severity: critical]: interactiveResume/style.css:45 / index.html:44 — `#6666ff` on `#FFFFFF` = 4.28:1; just below the 4.5:1 AA threshold for normal text — Darken brand purple to `#5454d4` or bolder (achieves 4.54:1)**

This affects the `.selectedState` text class and the `#6666ff` border/box-shadow color used as decorative text elsewhere. Title container text (`#FFFFFF` on `#6666ff`) has the same ratio from the other direction and also fails for normal-weight body text.

**SECURITY [severity: critical]: interactiveResume/ganttChart.js:366–374 — HTML string assembled via string concatenation then injected with `innerHTML` — Build DOM nodes programmatically (`createElement`/`appendChild`) instead of an HTML string**

Description bullet points include raw `<strong>` tags constructed via string concatenation (`str += '<li>' + desc + '</li>'`) and injected via `descriptionOutput.innerHTML`. Data is currently hardcoded so there is no immediate XSS risk, but the pattern is unsafe by design. Any future CMS or API integration would be a direct XSS sink.
